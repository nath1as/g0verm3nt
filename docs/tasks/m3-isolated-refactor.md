# M3 isolated TypeScript refactor evaluator

The first fixed development task is `m3/typescript-refactor/trim-prefix@1`. Its baseline, editable-path allowlist, evaluator reference and pinned Bubblewrap profile are checked into the harness. A patch is a restricted full-file artifact bound to the exact baseline source fingerprint; it cannot add files or change evaluator-owned tests.

The evaluator materializes a fresh workspace, binds it read-only into a Linux Bubblewrap namespace, disables the network, limits address space to 1 GiB, CPU time to five seconds and wall time to ten seconds, then runs the fixture's Bun test command. The evaluator source remains outside the task workspace. The host's RLIMIT_NPROC cannot be lowered before unprivileged user-namespace creation on this system, so the profile records no enforced process-count cap. Do not treat this as Gate B isolation completion.

Offline tests cover allowed, stale, malformed, traversal and non-editable patches plus evaluator failure and timeout outcomes. A completed evaluation persists the frozen source and patch, their hashes, evaluator/profile hashes, command result and terminal outcome under its run; when a provider attempt supplied the patch, that completed attempt must belong to the same run. Model output is accepted only as a canonical restricted JSON artifact; prose, fenced JSON, unknown fields and duplicate keys are rejected before evaluation. An external capability check ran the known-good patch through the actual namespace and obtained all three trusted tests passing. A live coding task remains separate work.

`m3-refactor [variant-ref]` is the durable end-to-end command. It starts a fresh run, commits provider intent before invoking the Codex CLI, parses the terminal text fail-closed, evaluates an accepted patch, records the result, and closes the run.
